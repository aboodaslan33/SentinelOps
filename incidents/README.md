## Report template

Every report in this folder uses the same structure. Copy this skeleton for a new incident.

```markdown
# Incident Report — INC-YYYY-NNN

> LABORATORY DATA statement

## 1. Incident summary
| Incident ID | Date | Time (UTC) | Alert name | Wazuh rules | Severity |
| Affected host | User | Source IP | Detection source | Analyst | Final status |

## 2. Description          What happened, in plain language
## 3. Timeline (UTC)       Every relevant event with its source and evidence
## 4. Indicators           IPs, accounts, hashes, paths, commands, event IDs
## 5. Investigation        The questions asked, the queries run, the answers found
## 6. MITRE ATT&CK         Tactic / technique / ID / evidence for each
## 7. Findings             Numbered, evidence-backed conclusions
## 8. Response actions     What was done, when, by whom, with what result
## 9. Recommendations      Prioritised, with rationale
## 10. Lessons learned     What worked, what did not, detection gaps raised
Final status: ...
```

### Writing standards applied

| Rule | Reason |
|---|---|
| All timestamps in **UTC** | Mixed time zones silently break timelines |
| Every claim backed by a specific artefact | "Probably" is not a finding |
| Record what was **not** found, and where you looked | Prevents the same ground being re-covered |
| Never include passwords, tokens, real user names or real internal IPs | Reports get shared |
| State the limits of the telemetry | An unstated gap becomes a false conclusion |
| Separate **findings** (evidence) from **recommendations** (opinion) | Different audiences read each |
