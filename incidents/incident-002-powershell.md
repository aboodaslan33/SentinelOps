# Incident Report — INC-2026-002

> **LABORATORY DATA.** Generated by the lab owner in an isolated virtual environment using the
> benign script `Invoke-LabPowerShellActivity.ps1`. No malware, no real payload and no external
> infrastructure were involved. The "downloaded file" was a text file served by a lab VM.

## 2. Description

At 13:47:11 UTC, `powershell.exe` was launched on `WIN-SOC-EP01` by the standard user account
`labuser` with a command line combining three evasion-associated switches — a hidden window, a
bypassed execution policy, and a Base64-encoded command:

```
powershell.exe -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -EncodedCommand <Base64>
```

Sysmon recorded the process (EID 1) and rule `100111` alerted at Medium. Two seconds later,
PowerShell script block logging (Event ID **4104**) recorded the **decoded** content, which
contained a download cradle using `Net.WebClient`. Rule `100113` escalated the incident to
High. Sysmon EID 3 then confirmed an outbound TCP connection from `powershell.exe` to
`192.168.56.30:8000`, and Sysmon EID 11 recorded a file written to the user's `%TEMP%`.

This is the canonical **"encoded PowerShell download cradle"** pattern. In this lab the
retrieved content was a harmless text file placed on a lab VM for the exercise.

## 5. Investigation

**Q1 — What did the encoded command actually do?**
Decoded **offline** (decoding is not executing):

```powershell
[Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('<BASE64>'))
```

Result: a `Net.WebClient` download cradle pointing at `http://192.168.56.30:8000/lab-test.txt`.
The same content appeared independently in the 4104 script block event — **two independent
sources agreeing is what turns a suspicion into a finding.**

**Q2 — What launched it?**
Process tree reconstructed from `ParentProcessGuid`:

```
explorer.exe (PID 3120, labuser)
  └── cmd.exe (PID 4812)
        └── powershell.exe (PID 5140)  <-- alert
```

The chain terminates at `explorer.exe`, i.e. **a user action at the keyboard**, not a document
macro and not a remote-execution service. Had the parent been `winword.exe`, rule `100112`
would have fired and the incident would have been treated as phishing.

**Q3 — Did the download succeed?**
Yes. Sysmon EID 3 shows the connection to `192.168.56.30:8000` and EID 11 shows the file
written to `%TEMP%`. The file was hashed (SHA256 recorded in the evidence folder) and
confirmed to be the benign lab text file.

**Q4 — Did anything execute from the retrieved content?**
No. `DownloadString` returns text to a variable; there was no `Invoke-Expression`/`IEX` of the
result and no subsequent process creation from PowerShell. Sysmon EID 5 shows the process
exited 7 seconds later with no child processes.

**Q5 — Was there persistence?**
Checked: registry Run keys (Sysmon EID 12/13), Startup folder (EID 11), scheduled tasks
(4698), services (7045), new accounts (4720). **None found.**

**Q6 — Did it run elevated?**
No. `integrityLevel: Medium` and no 4672 for the session. The blast radius was limited to
`labuser`'s own profile.

**Q7 — Any defence tampering?**
Rule `100115` did not fire. Defender exclusions and audit policy were checked manually and were
unchanged.

**Queries used**

```
rule.id:(100110 OR 100111 OR 100113 OR 100114)
data.win.system.eventID:4104 AND agent.name:"WIN-SOC-EP01"
data.win.eventdata.processGuid:"{...}"          # pivots to EID 3, 11, 5
data.win.eventdata.parentImage:*cmd.exe
```

## 7. Findings

1. **An obfuscated PowerShell download cradle executed successfully** under a standard user
   account and retrieved content from a remote host.
2. **Script block logging was decisive.** The command line alone showed only Base64; Event
   4104 revealed the exact URL and method. Without it this alert would have needed manual
   decoding to be actionable — a direct argument for enabling it everywhere.
3. **No second-stage execution occurred.** The retrieved content was stored, not executed.
4. **No elevation and no persistence.** Impact was confined to the `labuser` profile.
5. **Detection layering worked as designed:** Medium on the command line (`100111`) → High on
   the decoded intent (`100113`) → corroboration from the network (`100114`). Each layer
   independently confirmed the others.

## 9. Recommendations

| # | Recommendation | Priority | Rationale |
|---|---|---|---|
| 1 | Enable Defender ASR rule *"Block Office applications from creating child processes"* | High | Closes the most common real-world path to this exact chain |
| 2 | Deploy PowerShell **Constrained Language Mode** for standard users | High | Blocks `New-Object Net.WebClient` for non-admins |
| 3 | Remove PowerShell v2 from all endpoints | High | v2 has no script block logging and is used to downgrade-evade it |
| 4 | Add a rule for `IEX`/`Invoke-Expression` **applied to downloaded content** at level 13 | Medium | Separates "downloaded" from "downloaded and executed" |
| 5 | Alert on any `powershell.exe` outbound connection to a non-allowlisted destination | Medium | `100114` currently alerts on all destinations — noisy at scale |
| 6 | Enable AppLocker/WDAC to block execution from `%TEMP%` | Medium | Prevents the natural next step of this chain |
| 7 | Add user-awareness training on copy-pasted PowerShell commands | Low | The parent chain showed a deliberate user action |

---

## 10. Lessons learned

* **Script block logging is the highest-value control in this lab.** It converted an opaque
  Base64 blob into a complete IOC list in one event.
* **Process ancestry decided the severity.** `explorer.exe` as the root made this a
  user-initiated action; `winword.exe` would have made it a phishing incident with a very
  different response.
* **Detection gap identified:** there is no rule distinguishing "content downloaded" from
  "content downloaded and executed". Recommendation #4 raised as SO-DET-002-B.
* **Process termination events (EID 5) mattered** — knowing the process lived only 7 seconds
  ruled out interactive attacker use.

**Final status: CLOSED — True Positive (authorised laboratory simulation), contained, no
compromise.**
